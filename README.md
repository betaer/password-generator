## 为什么使用

- **安全随机**：随机数据来自浏览器原生 Web Crypto API，不使用 `Math.random()`。
- **本地生成**：密码、PIN、记忆短语和输入内容不发送到项目服务器。
- **专业规则**：可控制长度、字符类型、符号比例、首尾类型、重复字符和排除字符。
- **模式感知分析**：同时展示理论搜索空间、zxcvbn 可预测模式结果与三种攻击模型，并明确估算边界。

## 安全随机策略

### Web Crypto 与拒绝采样

所有核心随机选择均使用：

```js
crypto.getRandomValues(buffer)
```

随机索引没有直接使用 `randomUint32 % size`，而是先计算可被候选池大小整除的接受区间，超出区间就重新取样。这种**拒绝采样（rejection sampling）**可以避免词库或字符池大小不能整除 `2³²` 时产生的 modulo bias。

### 随机密码规则

- 小写字母、大写字母、数字、符号可独立启用，并支持一键全选。
- “每类至少 1 个”会保证已启用字符类型进入结果。
- 符号支持指定比例范围或固定数量；密码长度缩小时，固定数量会同步收敛。
- 首字符与尾字符类型会与已启用字符类型联动，无法满足的选项自动禁用。
- 可排除 `iIlL1`、`0Oo` 等视觉近似字符，也可输入自定义排除字符。
- 默认随机密码为 32 位、四类字符全选、符号占比 20%～80%、生成 1 个。

| 金融与 Web3 | 1,024 | 10 bits | 主题词包按需加载 |
| 科学与太空 | 1,024 | 10 bits | 主题词包按需加载 |
| 商务与办公 | 1,024 | 10 bits | 主题词包按需加载 |

不同词包在相同词数下的理论熵并不相同：

| 词包 | 每个词理论熵 | 4 个词 | 6 个词 |
|---|---:|---:|---:|
| 1,024 主题词包 | 10 bits | 40 bits | 60 bits |
| 1,296 简单词库 | 约 10.34 bits | 约 41.36 bits | 约 62.04 bits |
| 7,776 标准词库 | 约 12.92 bits | 约 51.70 bits | 约 77.55 bits |

主题词包更聚焦、更容易组织记忆，但候选池小于标准词库，所以并不会因为“更专业”而更安全。**主题词包建议至少 6 个词**；需要更高随机空间时优先选择 7,776 词标准词库或增加词数。

每词理论熵按下式计算：

```text
每词理论熵 = log₂(实际可抽取词数)
整条理论熵 = 单词数量 × log₂(实际可抽取词数)
```

例如，从 7,776 词标准词库独立、均匀地抽取 12 个词，理论熵约为 `12 × log₂(7,776) ≈ 155.1 bits`。该结论依赖每个词都由安全随机数独立、均匀抽取；用户输入的场景描述不作为随机种子，也不计入熵。

词包由项目自身托管，完整词包带版本、数量和 SHA-256 校验信息。两个冷启动小型模块压缩后内置到 HTML，7,776 词标准词库继续异步加载，兼顾首次打开稳定性和页面体积。

## PIN 规则

PIN 生成器可组合以下约束：

- 是否允许以 `0` 开头。
- 是否排除明显弱 PIN。
- 是否允许数字重复。
- 是否限制长度超过 2 的升序或降序连续数字。

弱 PIN 过滤不是仅靠少量硬编码示例。项目从固定版本的 SecLists 数据构建本地风险索引，覆盖完整的 **10,000 个四位 PIN 排名**和 **68,202 个唯一六位数字 PIN**；运行时还识别全相同数字、短周期循环、升降序列、日期样式和键盘路径。默认拦截高频排名与明显弱模式，数据只从本站静态资源加载。启用连续数字限制时，工具使用状态计数计算当前规则下的可能组合数，而不是简单套用 `10ⁿ`。

这些过滤只减少容易预测的组合，不能让短 PIN 获得与长随机密码相同的安全性。

## 强度分析如何计算

强度面板会在每次生成后重新分析**实际结果**，不会只沿用设置面板的目标等级。

- 随机密码：先按实际长度、字符类别、位置组合和字符池计算理论空间，再由 `zxcvbn-ts` 识别字典词、重复、序列、键盘路径等可预测模式。
- 记忆短语：依据实际词包数量和实际单词数计算。
- PIN：结合有效组合空间、完整常见 PIN 排名和规则模式分析。
- 有效猜测次数：取“理论平均猜测次数”与“模式分析猜测次数”中更保守的一项，避免把理论组合空间误当成实际攻击复杂度。

页面同时展示三种攻击模型，而不是把单一速度包装成确定事实：

| 攻击模型 | 默认速度 | 含义 |
|---|---:|---|
| 在线限速攻击 | 100 次/小时 | 登录限速、锁定、验证码或多因素认证存在时的示意估算 |
| 慢速密码哈希 | 10⁴ 次/秒 | Argon2id、scrypt、bcrypt、PBKDF2 等离线验证的示意估算 |
| 快速离线哈希 | 10¹⁰ 次/秒 | 数据库泄露、快速哈希和高度并行硬件下的严苛估算 |

`zxcvbn` 是**模式估算器**，不是密码熵的来源；记忆短语继续按实际词包与独立抽取次数计算。三种时间都按平均搜索一半候选空间估算。**这些结果是攻击模型估算，不是安全保证。** 服务限速、哈希参数、硬件、泄露、重复使用、钓鱼和恶意终端都可能改变实际风险。

## 安全实现与可验证性

```text
Browser CSPRNG → Rejection Sampling → 模式感知分析 → 本地结果
```

- 密码、PIN、记忆短语、用户输入和生成历史属于**密码数据平面**，只在当前浏览器中生成与分析。历史记录只使用 `sessionStorage`，不会跨浏览器会话持久保存；关闭当前标签页后自动清除，也可随时清空。
- `zxcvbn`、PIN 风险库和词包属于**静态资源平面**，从本站同源路径加载；请求中不包含生成值。
- Google Analytics 只承担匿名访问统计；代码中没有 `generated_value` 事件参数，也不发送密码、PIN、记忆短语或输入内容。
- 可打开浏览器 **DevTools → Network**，生成并复制若干结果，亲自检查网络请求中不存在生成内容。

Web Crypto 不可用时工具会停止生成，不会回退到 `Math.random()`。第三方组件、语料版本和许可证见 [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)。

## 格式测试方案

| 分组 | 内置方案 |
|---|---|
| 数字场景 | 6 位银行卡密码、4 位银行卡密码、16 位银行卡号、19 位银行卡号 |
| 钱包地址样式 | ETH `0x + 40 Hex`、TRON `T + Base58`、BTC Legacy、BTC P2SH、BTC Bech32 |
| 私钥样式 | BTC / ETH / TRON 的 64 位十六进制字符串 |

> 这些方案只生成符合指定**长度、前缀和字符集外观**的测试字符串。它们不执行 Luhn 校验、Base58Check / Bech32 校验和、公钥推导、曲线有效性验证或链上检查，不能作为真实银行卡号、钱包地址或私钥使用。

## 隐私与数据边界

| 数据 | 处理方式 |
|---|---|
| 密码、PIN、记忆短语和输入内容 | 在当前浏览器内生成与分析，不进入网络请求或统计参数 |
| 设置 | 保存到浏览器本地存储，便于下次恢复 |
| 历史记录 | 仅存于当前标签页的 `sessionStorage`；不会跨浏览器会话持久保存，关闭标签页后自动清除，也可随时清空 |
| 词包 | 从本站静态资源按需读取，不调用第三方随机词 API |
| Google Analytics | 用于匿名访问统计；没有 `generated_value`，不发送凭据或输入内容 |

剪贴板写入仍受浏览器权限与安全上下文限制；若浏览器拒绝权限，页面会保留结果供手动复制。

## 能力边界
