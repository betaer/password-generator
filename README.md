# Password Generator｜密码生成器

[简体中文](README.md) · [English](docs/readme-en.md)


浏览器本地运行的专业密码生成器，支持**随机密码、记忆短语与 PIN**，并提供细粒度生成规则、格式测试方案和基于每次实际结果的量化强度分析。

## 为什么使用

- **安全随机**：随机数据来自浏览器原生 Web Crypto API，不使用 `Math.random()`。
- **本地生成**：密码、PIN、记忆短语和输入内容不发送到项目服务器。
- **专业规则**：可控制长度、字符类型、符号比例、首尾类型、重复字符和排除字符。
- **可量化分析**：展示字符组成、理论熵、穷举次数与预计破解时间，并明确估算前提。

## 安全随机策略

### Web Crypto 与拒绝采样

所有核心随机选择均使用：

```js
crypto.getRandomValues(buffer)
```

随机索引没有直接使用 `randomUint32 % size`，而是先计算可被候选池大小整除的接受区间，超出区间就重新取样。这种**拒绝采样（rejection sampling）**可以避免词库或字符池大小不能整除 `2³²` 时产生的 modulo bias。

### 随机密码规则

- 小写字母、大写字母、数字、符号可独立启用，并支持一键全选。
- “每类至少 1 个”会保证已启用字符类型进入结果。
- 符号支持指定比例范围或固定数量；密码长度缩小时，固定数量会同步收敛。
- 首字符与尾字符类型会与已启用字符类型联动，无法满足的选项自动禁用。
- 可排除 `iIlL1`、`0Oo` 等视觉近似字符，也可输入自定义排除字符。
- 默认随机密码为 32 位、四类字符全选、符号占比 20%～80%、生成 1 个。

## 记忆短语与词库

| 词包 | 数量 | 每词理论熵 | 加载方式 |
|---|---:|---:|---|
| 简单词库 | 1,296 | 约 10.34 bits | 内置启动词包 |
| 标准词库 | 7,776 | 约 12.92 bits | 进入记忆短语后按需加载 |
| 科技与软件 | 1,024 | 10 bits | 主题词包按需加载 |
| 云计算与运维 | 1,024 | 10 bits | 主题词包按需加载 |
| 网络与安全 | 1,024 | 10 bits | 主题词包按需加载 |
| 金融与 Web3 | 1,024 | 10 bits | 主题词包按需加载 |
| 科学与太空 | 1,024 | 10 bits | 主题词包按需加载 |
| 商务与办公 | 1,024 | 10 bits | 主题词包按需加载 |

每词理论熵按下式计算：

```text
每词理论熵 = log₂(实际可抽取词数)
整条理论熵 = 单词数量 × log₂(实际可抽取词数)
```

例如，从 7,776 词标准词库独立、均匀地抽取 12 个词，理论熵约为 `12 × log₂(7,776) ≈ 155.1 bits`。该结论依赖每个词都由安全随机数独立、均匀抽取；用户输入的场景描述不作为随机种子，也不计入熵。

词包由项目自身托管，完整词包带版本、数量和 SHA-256 校验信息。两个冷启动小型模块压缩后内置到 HTML，7,776 词标准词库继续异步加载，兼顾首次打开稳定性和页面体积。

## PIN 规则

PIN 生成器可组合以下约束：

- 是否允许以 `0` 开头。
- 是否排除明显弱 PIN。
- 是否允许数字重复。
- 是否限制长度超过 2 的升序或降序连续数字。

弱 PIN 过滤覆盖全相同数字、短模式循环、连续序列和常见组合，例如 `0000`、`1111`、`1212`、`1234`、`4321`、`123456`。启用连续数字限制时，工具使用状态计数计算当前规则下的可能组合数，而不是简单套用 `10ⁿ`。

这些过滤只减少容易预测的组合，不能让短 PIN 获得与长随机密码相同的安全性。

## 强度分析如何计算

强度面板会在每次生成后重新分析**实际结果**，不会只沿用设置面板的目标等级。

- 随机密码：结合实际长度、字符类别、各类别位置组合、字符池、重复单元和简单连续序列估算。
- 记忆短语：依据实际词包数量和实际单词数计算。
- PIN：在字符组成基础上进一步识别弱组合与连续模式并降级。
- 穷举次数：由估算熵换算为候选空间。
- 预计破解时间：默认按每秒尝试 1 万次、平均搜索一半空间估算。

破解时间是用于比较方案的**理论模型**，实际速度会受到服务端限速、密码哈希算法、硬件、攻击方式和密码是否已泄漏等因素影响，不是安全承诺。

## 格式测试方案

| 分组 | 内置方案 |
|---|---|
| 数字场景 | 6 位银行卡密码、4 位银行卡密码、16 位银行卡号、19 位银行卡号 |
| 钱包地址样式 | ETH `0x + 40 Hex`、TRON `T + Base58`、BTC Legacy、BTC P2SH、BTC Bech32 |
| 私钥样式 | BTC / ETH / TRON 的 64 位十六进制字符串 |

> 这些方案只生成符合指定**长度、前缀和字符集外观**的测试字符串。它们不执行 Luhn 校验、Base58Check / Bech32 校验和、公钥推导、曲线有效性验证或链上检查，不能作为真实银行卡号、钱包地址或私钥使用。

## 能力边界

- 本项目是生成与分析工具，不是密码管理器、钱包、密钥托管服务或硬件随机数设备。
- 生成高价值主密码或密钥材料时，应同时评估浏览器、设备、扩展程序、剪贴板和终端环境的安全性。
