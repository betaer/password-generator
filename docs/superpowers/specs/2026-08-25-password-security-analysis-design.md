# Password Generator 安全分析升级设计规格

日期：2026-08-25  
状态：已获方向批准，待实现计划与代码落地

## 1. 目标

在保持 GitHub Pages 单页静态应用、浏览器本地生成和首屏稳定性的前提下，补齐以下能力：

1. 使用 `zxcvbn-ts` 识别常见密码、字典词、键盘路径、日期、重复、序列和 l33t 变形。
2. 引入完整四位 PIN 频率排名，并扩充六位常见 PIN 识别。
3. 把理论生成空间、模式猜测成本和攻击速度模型彻底分离。
4. 将单一“每秒 1 万次”破解时间升级为三种攻击模型。
5. 增加可核验的安全说明，清楚区分凭据数据面、静态资源面和匿名统计面。

## 2. 不变量

- 密码、PIN、记忆短语、场景描述和剪贴板内容不得进入网络请求、日志或统计参数。
- 所有业务随机选择必须使用 `crypto.getRandomValues()` 和拒绝采样。
- 不使用 `Math.random()` 参与密码、PIN、词语、分隔符、洗牌或格式数据生成。
- zxcvbn、PIN 数据和词包全部由项目同域托管，不依赖运行时第三方 CDN。
- zxcvbn 或 PIN 数据加载失败时，生成能力必须继续可用，并回退到现有本地估算器。
- 记忆短语按实际词包大小与词数计算，zxcvbn 不得覆盖其已知生成空间。
- 攻击时间必须标记为模型估算，不得展示为安全保证。

## 3. 三层分析模型

### 3.1 理论生成空间

理论生成空间描述“按照当前生成规则，工具可能生成多少种结果”。

- 随机密码：继续按字符池、长度、符号数量、首尾约束、禁止重复等规则精确或近似计算。
- 记忆短语：`词包实际数量 ^ 单词数量`，附加随机大小写和随机分隔符时单独增加对应空间。
- PIN：使用有效状态计数，纳入前导零、禁止重复、连续数字限制和弱 PIN 过滤。
- 格式方案：按随机部分长度、字母表和固定前缀计算。

均匀生成结果的平均理论尝试次数为：

```text
theoreticalAverageGuesses = theoreticalSearchSpace / 2
```

### 3.2 模式猜测成本

模式猜测用于回答“攻击者是否会在完整穷举之前猜到这个实际结果”。

- 随机密码：使用 zxcvbn 的 `guesses`，并保留现有重复、序列和实际组成估算器作为回退。
- 四位 PIN：使用完整频率排名作为直接猜测顺序。
- 六位 PIN：使用常见六位 PIN 排名、zxcvbn 数字模式识别与现有规则引擎。
- 其他 PIN：使用 zxcvbn 与重复、循环、连续、日期、键盘路径等规则。
- 记忆短语：不使用 zxcvbn 的普通字典评分覆盖已知词包模型；仅可把明显重复的整词序列作为补充风险提示。

有效平均猜测次数：

```text
effectiveGuesses = min(theoreticalAverageGuesses, patternGuesses)
```

如果模式分析器尚未加载或不适用，则使用理论平均尝试次数。

### 3.3 攻击速度模型

同一个 `effectiveGuesses` 分别换算为三个时间，不再让攻击速度反向决定熵值或强度等级。

| 模型 | 默认速度 | 含义 |
|---|---:|---|
| 在线限速攻击 | 100 次/小时 | 网站存在登录限速、锁定、验证码或多因素认证 |
| 慢速密码哈希 | 10⁴ 次/秒 | Argon2id、scrypt、bcrypt、PBKDF2 等慢速离线验证的示意模型 |
| 快速离线哈希 | 10¹⁰ 次/秒 | 数据库泄露且使用快速哈希或攻击硬件高度并行的严苛模型 |

时间换算：

```text
estimatedSeconds = effectiveGuesses / guessesPerSecond
```

统一免责声明：

> 这些结果是攻击模型估算，不是安全保证。实际结果还受登录限速、哈希算法、工作因子、硬件规模、密码泄露、钓鱼和重复使用影响。

## 4. 强度等级

L1～L8 改为依据有效猜测空间的 bit 值，不再依据固定的每秒 1 万次破解时间划级：

| 等级 | 有效猜测空间 | 文案 |
|---|---:|---|
| L1 | `< 20 bits` | 瞬间破解 |
| L2 | `20～<32 bits` | 极易破解 |
| L3 | `32～<40 bits` | 容易破解 |
| L4 | `40～<52 bits` | 有一定风险 |
| L5 | `52～<64 bits` | 较难破解 |
| L6 | `64～<80 bits` | 很难破解 |
| L7 | `80～<112 bits` | 极难破解 |
| L8 | `≥112 bits` | 几乎无法破解 |

强度等级描述生成与猜测空间，不直接等同于任何一种破解时间。默认 32 位随机密码仍会达到 L8；256/512 位用于超长凭据、测试数据或密钥材料，并不需要人为拆出更高的密码等级。

## 5. zxcvbn-ts 集成

### 5.1 选择

- 使用维护中的 `@zxcvbn-ts/core`。
- 使用 `@zxcvbn-ts/language-common` 的常见密码与键盘图谱。
- 不接入联网的 Pwned Password Matcher。
- 第一版不加载完整英文人名和百科词典，避免为生成器场景引入数 MB 字典；后续可根据实际分析效果增加经过筛选的本地字典。

### 5.2 构建与运行

- 在开发依赖中固定 zxcvbn-ts 与打包工具版本。
- 生成一个可提交、可缓存的本地版本化资源，例如：

```text
assets/vendor/zxcvbn-analyzer.v1.min.js
assets/vendor/zxcvbn-LICENSE.txt
```

- `index.html` 不内联该资源。
- 应用首屏完成后通过 `requestIdleCallback` 预热；不支持时在首次需要模式分析时加载。
- 使用单例 Promise，避免重复请求和重复初始化。
- 加载状态分为 `idle / loading / ready / fallback`，分析面板不得因加载失败报错或阻止生成。
- 版本、依赖和字典来源写入 `THIRD_PARTY_NOTICES.md`。

## 6. Common PIN 数据

### 6.1 四位 PIN

- 使用 SecLists `four-digit-pin-codes-sorted-by-frequency-withcount.csv`。
- 数据包含全部 10,000 个四位组合。
- 构建阶段转换为紧凑排名表，运行时不解析 10,000 行 CSV。
- 数据资源独立存放并进入 PIN 页面时按需加载。

建议资源：

```text
assets/data/pin-risk.v1.json
assets/data/pin-risk-source.txt
```

### 6.2 六位 PIN

- 从 SecLists 的常见凭据语料中离线筛选纯六位数字，按原始出现顺序生成排名。
- 数据来源、上游版本和 SHA-256 固定在构建脚本与来源说明中。
- 不宣称覆盖全球全部六位 PIN，只称“常见六位 PIN 语料排名”。

### 6.3 风险分级与过滤

| 条件 | 行为 |
|---|---|
| 四位排名前 100 | 极常见，强制降至最低风险等级；开启弱 PIN 过滤时拒绝 |
| 四位排名 101～500 | 高风险；开启弱 PIN 过滤时拒绝 |
| 四位排名 501～2,000 | 较常见，降低有效猜测次数并给出排名提示 |
| 六位常见语料前 1,000 | 开启弱 PIN 过滤时拒绝 |
| 重复、循环、连续、日期、键盘路径 | 无论数据库是否命中都继续执行规则判断 |

弱 PIN 生成继续采用“均匀生成候选后拒绝不合格结果”的方式，确保允许集合内的结果保持均匀分布。

## 7. UI 设计

### 7.1 主面板保持紧凑

密码强度分析仍显示：

- 字符多样性
- 理论熵/有效猜测空间
- 穷举或模式猜测次数
- 预计破解时间

“预计破解时间”主值显示更保守的：

```text
快速离线：约 X
```

### 7.2 三种攻击模型放入加宽气泡

预计破解时间后的信息图标展示三行实时结果，标题加粗：

```text
在线限速攻击
约 X · 100 次/小时
网站有登录限速、锁定、验证码或多因素认证。

慢速密码哈希
约 X · 10⁴ 次/秒
用于 Argon2id、scrypt、bcrypt、PBKDF2 等示意估算。

快速离线哈希
约 X · 10¹⁰ 次/秒
用于数据库泄露且攻击硬件高度并行的严苛估算。
```

- 气泡全局采用统一白字、统一字重；仅三个模型标题加粗。
- 桌面端 hover 展示；移动端单击持续展示，点击气泡外关闭。
- 气泡宽度使用现有全局加宽规格，段落之间保留明确空行。
- 黄色建议条使用快速离线模型，但明确写出模型名称。

### 7.3 PIN 风险信息

PIN 命中数据库时，在强度气泡或建议区显示：

```text
常见四位 PIN 排名：第 23 位
攻击者通常会优先尝试该组合。
```

未加载排名数据时不展示虚假排名，只使用规则判断。

### 7.4 安全与可验证性

新增“安全说明”弹窗或抽屉，展示：

```text
Browser CSPRNG
→ Unbiased Selection
→ Mode-aware Analysis
→ Local Secret Data Plane
```

明确说明：

- 生成值不会进入 Google Analytics 或其他网络请求参数。
- 词包、zxcvbn 和 PIN 数据文件属于静态资源请求。
- 当前历史记录保存在 `sessionStorage`，仅限当前浏览器会话，可删除或清空。
- 用户可在 DevTools → Network 中生成新密码，核对请求参数不含生成值。

不得使用“Zero Network Requests”或“No password storage”这类与当前实现不符的绝对表述。

## 8. 测试要求

### 8.1 随机安全

- 静态扫描业务代码不得出现 `Math.random()`。
- 对密码、PIN、词语、随机分隔符和洗牌验证拒绝采样调用链。
- 使用可注入的确定性 Web Crypto 测试拒绝边界与重采样。

### 8.2 zxcvbn

- `password123`、`p@ssw0rd`、键盘路径、日期和重复模式必须显著低于等长随机结果。
- zxcvbn 加载失败时回退分析可用。
- 生成值不得出现在动态模块 URL、错误日志或统计事件中。

### 8.3 PIN

- 校验四位排名表恰好覆盖 10,000 个唯一 PIN。
- 校验已知头部排名，例如 `1234`、`1111`、`0000`、`1212`。
- 校验六位语料无非数字和重复项。
- 开启弱 PIN 过滤后，头部常见值、循环值和长连续序列不得生成。

### 8.4 攻击模型

- 三种模型使用同一有效猜测次数，时间比例与速度比例一致。
- 熵值和等级不得随所选攻击速度变化。
- 超大结果不得出现 `Infinity`、科学计数格式溢出或页面崩溃。

### 8.5 UI 与兼容性

- 桌面 hover、移动点击、点击外部关闭均需覆盖。
- zxcvbn/PIN 数据加载中和失败状态不得造成布局跳动。
- 首屏、随机密码、PIN、记忆短语及历史记录现有交互必须回归测试。
