# V2.1 紧凑批量生成结果设计

## 目标与已确认方向

用户已明确选择 V1.7.5 风格的紧凑批量列表：同一次请求生成 1～100 条结果时，结果值是主内容；相同的生成器数学与攻击场景只在列表底部展示一次；每条结果可以单独复制、隐藏、重新生成和删除。

当前 V2.1 每条结果重复渲染“精确生成器指标、观察模式估算、攻击场景估算、生成模型详情”，导致一屏无法浏览两条结果。新设计必须减少重复，但不能把逐条字符串模式分析错误宣称为批次公共结论。

## 备选方案与选择

1. 每条保留完整安全卡：数学信息最完整，但重复严重，否决。
2. 只在第一条结果显示完整安全卡：减少部分重复，但安全说明的归属不清楚，删除第一条后结构突变，否决。
3. 紧凑结果列表 + 批次级安全说明 + 行内模式风险提示：公共数学只展示一次，逐条差异仍然诚实保留，采用。

## 页面结构

结果区从上到下分为四层：

1. 批量操作栏：重新生成全部、复制全部、清空结果。单条结果时“复制全部”显示为“复制”。
2. 紧凑结果列表：每行包含序号、明文结果、类型相关摘要和图标操作。
3. 批次级安全说明：默认折叠；摘要行只显示最重要的公共强度数字和本批观察模式状态，展开后显示一次完整指标、攻击场景与生成模型详情。
4. 生成记录 History：保留现有默认折叠结构。

一屏应能浏览至少三条常规 20～32 位密码；不得继续用每条独立大卡和深色 92 像素结果面板。

## 紧凑结果行

每行使用稳定三列布局：序号、结果内容、操作区。

- 结果默认明文；隐藏时使用固定长度占位符，切换不改变行高。
- 结果内容单行截断；悬停或键盘聚焦显示完整值气泡；助记词、复合 API Secret 和超长内容允许受控多行摘要。
- 摘要按类型显示：Password 显示长度与四类字符计数；Passphrase 显示词数；PIN 显示位数与批内唯一策略；Token/API Secret/Hex 显示随机位数与编码；UUID 显示版本且注明“标识符”；Random Bytes 显示字节数、编码和该条 SHA-256 的短摘要；BIP39 显示 ENT/CS、词数和语言。
- 操作使用现有 V2.1 图标体系：隐藏/显示、复制、重新生成、删除；Random Bytes 额外保留下载按钮。所有图标按钮有中文 `aria-label`、键盘焦点和气泡说明。
- Password/Passphrase 的观察模式为逐条状态：分析中显示中性信息图标；发现模式或启发式估算更保守时显示警告感叹号；详细原因仅在气泡内展示。未发现模式时不占用额外文案行。

## 批次级安全说明

同一原子批次的结果共享冻结的 mode/config，因此以下内容只显示一次：

- 精确生成器最小熵、香农熵、生成空间、期望猜测次数；
- 适用于该类型的攻击场景估算；
- 固定生成模型与配置快照说明；
- UUID、Random Bytes、BIP39、Token/API Secret/Hex、PIN 的类型专用安全边界。

批次摘要默认折叠。折叠标题显示“本批安全说明”、适用条数和 2～3 个最关键数值；术语解释收进信息气泡。展开后复用现有准确数学，不修改熵与概率模型。

观察模式不作为公共熵覆盖值。批次说明只聚合状态：已完成多少条、多少条发现常见模式；每条模式详情仍由行内感叹号承载。

UUID v7 时间戳、Random Bytes SHA-256 等逐条变化字段留在结果行摘要或气泡，不错误放进公共模型。

## 单条重新生成

单条重新生成必须沿用原批次的冻结请求，而不是读取用户随后修改但尚未重新生成的表单：

1. 完整批次生成成功后保存不含秘密的不可变 `{ mode, config }` 请求快照。
2. 点击某行重新生成时创建新的 generation job，数量为 1，并走现有 CompiledGenerator / Worker / Web Crypto / 原子批次流程。
3. 新结果成功且任务仍是当前 epoch 后，原子替换指定位置；失败或过期时保留旧结果。
4. PIN 开启批内唯一时，新结果不得与其余当前 PIN 重复；发生碰撞时有界重试，耗尽后给出错误且不改变原行。
5. 新结果加入启用中的 History；旧结果只有在不再被 History 引用时才清理可控字节。
6. 移除旧模式分析状态，为新结果启动独立 zxcvbn 分析；不自动复制。

批量生成、单条重新生成和模式切换共用同一 coordinator；生成期间禁用冲突操作，模式切换会取消未完成任务。

## 数据与组件边界

- `state.resultBatchRequest`：仅保存冻结的非秘密 mode/config；结果为空或切换模式时清除。
- `buildCompactResultRow(result, index)`：只负责逐条值、摘要、模式提示和操作。
- `buildBatchAssessment(results)`：只负责批次公共数学、聚合观察状态和折叠详情。
- `regenerateResult(id)`：负责请求快照、原子替换、去重、History、清理与分析协调。
- `updateResultAssessment(id)`：更新对应行的模式提示与唯一批次说明，不重建整个页面焦点上下文。

## 错误与安全边界

- 缺少批次请求快照、结果已删除、模式已切换或任务过期时 fail closed。
- 单条重新生成失败不删除旧结果、不写 History、不留下部分结果。
- Clipboard 仍只在显式复制时写入；重新生成不复制。
- DOM 和内存边界说明保持真实；不新增持久化秘密。
- 所有 secret 字符串仍无法可靠清零；可控 `Uint8Array` 按现有生命周期清理。

## 响应式与无障碍

- 桌面结果列表一行完成主要操作；移动端允许内容列占满第一行，图标操作保持至少 32 × 32 像素触控区。
- 320、390、430、1280 像素均不得产生页面横向溢出。
- 结果值、模式提示和按钮均可键盘访问；气泡支持 hover 与 focus；隐藏/显示使用 `aria-pressed`。
- 列表更新不使用位移动画，避免隐藏/显示和重新生成时页面晃动。

## 测试与验收

先写失败测试，再实现：

- 源代码契约：每条结果不再创建完整指标/攻击场景/模型详情；页面只有一个批次安全说明容器。
- 浏览器 E2E：生成 5 条密码后，一屏能看到至少 3 条；完整指标、观察聚合、攻击场景和模型详情各只出现一次。
- 模式 E2E：逐条分析状态在各自行内提示，聚合数字随分析更新。
- 单条重新生成 E2E：只替换指定 id/值，其余顺序和值不变；不写 Clipboard；History 与删除生命周期正确。
- PIN 唯一性：单条重新生成后仍与本批其他 PIN 不重复。
- 九类生成器：逐条摘要和批次安全语义正确，Random Bytes 下载、UUID 标识符、BIP39 校验信息不丢失。
- 响应式与交互：320/390/430/1280px 无溢出，复制、隐藏、重生成、删除、气泡、折叠和键盘操作正常。
- 运行完整 `npm run verify:v21`，独立代码复审通过后才允许发布。
